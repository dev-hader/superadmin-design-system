# Breadcrumb

## Purpose
Shows where the current page sits in the hierarchy (e.g. `Components › Pickers & Advanced`) at the top of every page head.

## Description
A flex row of `<span>` crumbs separated by 14px chevron icons, in tertiary small text, rendered inside `.page-head` above the `<h1>`. It is generated by the shared page-head helper (`H.pageHead(crumb, title, lead)` in `assets/js/app.js`), which interleaves a chevron icon before every crumb after the first. Note: the `TABS / SEGMENTED / BREADCRUMB` banner in `components.css` names the pattern, but the actual `.breadcrumb` rules live in `app.css` (`.page-head .breadcrumb`) — verify there, not in components.css.

## Variants
| Variant | Class | Use when |
|---|---|---|
| Default | `.breadcrumb` (inside `.page-head`) | Every doc/app page head |

## States
| State | Trigger | Appearance |
|---|---|---|
| Default | — | `--color-text-tertiary`, `--text-sm`, chevron separators |

No hover/active rules exist — the demo crumbs are plain `<span>`s, not links.

## Properties
| Property | How |
|---|---|
| Trail items | Array passed to `H.pageHead([...])`; each becomes a `<span>` |
| Separator | 14px chevron SVG auto-inserted between crumbs by the helper |

## Responsive Behaviour
No media queries target `.breadcrumb`. Keep trails to 2–4 levels so they fit narrow screens.

## Accessibility
- The styled implementation is plain spans; when crumbs must be clickable, wrap the row in `<nav aria-label="Breadcrumb">` in page code.
- **RTL:** the separator chevron mirrors automatically — `[dir="rtl"] .breadcrumb svg { transform: scaleX(-1); }` (app.css, `RTL MIRRORING` section). Layout order mirrors via logical properties.

## Dependencies
Tokens: text, spacing groups. JS: `H.pageHead` helper (`assets/js/app.js`) builds the markup; chevron comes from the shared icon set.

## Related Components
- [tabs.md](tabs.md) — lateral movement between sibling views; breadcrumb is vertical position in the hierarchy.
- [pagination.md](pagination.md) — position within one long list, not within the site tree.

## Usage Examples
- Docs pages: `Components › Pickers & Advanced` above the page title (rendered by `H.pageHead`).
- Any `.page-head` where the page is more than one level deep.

## Do
- Keep to 2–4 levels; the current page is always the last crumb.
- Let the shared `pageHead` helper render it rather than hand-writing crumbs.

## Don't
- Don't add a breadcrumb to top-level pages with no hierarchy above them.
- Don't restyle separators per page — the chevron icon and tertiary color are fixed.

## HTML Reference
```html
<!-- As emitted by H.pageHead(["Components", "Pickers & Advanced"], ...) -->
<div class="page-head">
  <div class="breadcrumb">
    <span>Components</span>
    <!-- HF.icon("chevron") separator SVG -->
    <span>Pickers &amp; Advanced</span>
  </div>
  <h1>Pickers &amp; Advanced</h1>
</div>
```

## CSS Reference
`assets/css/app.css` → `DOC CONTENT` section (`.page-head .breadcrumb`) and `RTL MIRRORING` section (chevron flip). The `components.css` banner `TABS / SEGMENTED / BREADCRUMB` references the pattern but contains no breadcrumb rules.
